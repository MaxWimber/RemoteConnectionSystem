Что проверяем: сведения о сервере, работа готовой программы, HTTPS на домене, проброс 8443/UDP.

ПЕРВЫЙ ЗАПУСК, DNS и роутер пока можно не менять

1. Распакуйте архив в C:\RCS\phase00.
2. Откройте PowerShell в этой папке.
3. Выполните:
   powershell -ExecutionPolicy Bypass -File .\test-phase.ps1
4. Выберите пункт 1, затем пункт 4.
5. Верните созданный в C:\RCS архив rcs-logs-*.zip.

ВТОРОЙ ЗАПУСК, после указаний по первым логам

Нужны изменённая A-запись и проброс 80/TCP и 8444/TCP, см. SETUP-SERVER.md в этой папке.

1. Откройте PowerShell от имени администратора.
2. Запустите меню и выберите пункт 2.
   Сценарий скачает официальный Caddy с GitHub, проверит контрольную сумму, создаст службу rcs-caddy под
   учётной записью LocalService и добавит правило брандмауэра только для caddy.exe на TCP 80 и 8444.
3. Откройте https://maxwimber.ru:8444/RemoteConnectionSystem/ с телефона через мобильный интернет.
4. Для проверки UDP временно включите в роутере проброс 8443/UDP и выберите пункт 3.
   Пока идёт ожидание, отправьте тестовый пакет с компьютера вне домашней сети, команда есть в SETUP-SERVER.md.
   После проверки обязательно выключите проброс 8443/UDP.
5. Выберите пункт 4 и верните архив логов.

ЧТО ОТПРАВЛЯЕТСЯ В ИНТЕРНЕТ

Пункт 1 запрашивает ваш внешний IP на api.ipify.org только для сравнения с DNS, сам адрес в отчёт не записывается.
Пункт 2 обращается к GitHub и к Let's Encrypt.

ОТКАТ

Пункт 5 удаляет службу и правило брандмауэра. Сертификаты и логи остаются в C:\ProgramData\RCS.
