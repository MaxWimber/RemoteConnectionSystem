# Безопасность

Система даёт удалённое управление всем компьютером, включая экран входа Windows. Взлом входа означает
полный доступ к машине, поэтому эти требования обязательны и не упрощаются ради удобства.

## Модель угроз

| Угроза | Защита |
|---|---|
| Подбор пароля | Argon2id, TOTP, ограничение попыток, журнал |
| Перехват трафика | HTTPS, HSTS, DTLS и SRTP |
| Кража cookie | `HttpOnly`, `Secure`, `SameSite=Strict`, короткий срок жизни, запрет встраивания |
| CSRF и межсайтовый WebSocket | `SameSite=Strict`, проверка `Origin`, заголовок `X-RCS-Request` |
| XSS | CSP без `unsafe-inline` для скриптов, безопасный вывод имён файлов |
| Выход за пределы папки файлов | Канонизация пути, отказ от ссылок, ограниченная учётная запись |
| Уязвимость в `rcs-web` | Отдельная учётная запись без прав администратора |
| Подделка медиапира | Отпечаток DTLS передаётся через авторизованный WSS |
| Сбой в момент удержания клавиш | `release_all` при любом разрыве |
| Секреты в журналах | Запрет на запись, проверка на этапе ревью |

## Обязательные правила публикации

| Порт | Когда открывается |
|---|---|
| 80/TCP | Фаза 0, только для Caddy: сертификат и переадресация на HTTPS |
| 8444/TCP | Фаза 0, только для Caddy, вместо закрытого внешнего 443 |
| 8443/UDP | Кратко проверяется в фазе 0 и закрывается; постоянно открывается только после закрытия Gate фазы 3 |

Прямой доступ к `rcs-web` снаружи запрещён. RDP, SMB и другие службы через роутер не публикуются.
Брандмауэр Windows разрешает входящие подключения только Caddy на 80 и 8444 и `rcs-agent` на 8443/UDP.

## Авторизация

- Пользователь один. Веб-регистрация отсутствует.
- Пароль и TOTP задаются только локально на сервере: `rcs-web set-password` и `rcs-web enroll-totp`.
- Пароль от 16 символов. Значений по умолчанию нет. Без настроенных секретов `rcs-web` не запускается.
- Хэш пароля: Argon2id, параметры OWASP не ниже `m=19456`, `t=2`, `p=1`.
- TOTP: RFC 6238, SHA-1, 6 цифр, 30 секунд, допуск ±1 шаг. Повтор уже принятого кода запрещён.
- Секрет TOTP хранится зашифрованным через DPAPI в контексте машины.
- 8 одноразовых кодов восстановления хранятся как хэши.
- Предварительная сессия после пароля живёт 5 минут и даёт доступ только к шагу TOTP.

## Ограничение попыток

- 5 ошибок за 15 минут с одного IP: блокировка IP на 15 минут.
- 20 ошибок за час суммарно: блокировка всех новых входов на 15 минут, запись в журнал.
- Реальный IP берётся из `X-Forwarded-For` только при подключении от `127.0.0.1`.
- Ответы не раскрывают, что именно неверно. Проверка не зависит от правильности начала пароля.

## Сессии и cookie

```text
__Secure-rcs_session=...; Path=/RemoteConnectionSystem/; Secure; HttpOnly; SameSite=Strict
```

- Случайный токен 256 бит. На сервере хранится только его SHA-256.
- Простой до 60 минут, активный поток продлевает простой.
- Абсолютный срок: 12 часов, затем повторный вход.
- Выход и истечение сессии немедленно закрывают WebSocket и вызывают `CloseSession`.
- Активна одна сессия, новый вход завершает предыдущую.

## Заголовки

Выставляет Caddy или `rcs-web`:

```text
Strict-Transport-Security: max-age=31536000
Content-Security-Policy: default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' blob: data:; connect-src 'self' wss://maxwimber.ru:8444; frame-ancestors 'none'; base-uri 'self'; form-action 'self'
X-Content-Type-Options: nosniff
Referrer-Policy: no-referrer
Permissions-Policy: camera=(), microphone=()
```

`includeSubDomains` не включается, пока не проверены поддомены.

## Файлы

- Корень задаётся в `files.root`. Системные диски и папки Windows запрещены проверкой при запуске.
- Запрещены `..`, абсолютные пути, альтернативные потоки NTFS (`:`), зарезервированные имена (`CON`, `NUL` и другие).
- Путь канонизируется и проверяется на нахождение внутри корня. Ссылки и точки повторной обработки не открываются.
- Файлы скачиваются с `Content-Disposition: attachment` и `X-Content-Type-Options: nosniff`.
- Удаление выполняется в `.rcs-trash`. Очистка только по явной команде пользователя.
- Запуск файлов через файловый API не предусмотрен.
- Учётной записи `rcs-web` выдаётся доступ только к `files.root`.

## Секреты

- Каталог: `%ProgramData%\RCS\secrets`. ACL: только SYSTEM, Администраторы и `NT SERVICE\rcs-web`.
- Секреты, сертификаты, `config.toml` с реальным IP и журналы не попадают в git.
- В журналы не пишутся пароли, коды, cookie, SDP и пути к личным файлам на уровне выше `debug`.

## Службы и канал

- `rcs-supervisor` не слушает сеть и выполняет минимум действий под SYSTEM.
- Агент разбирает данные из сети с проверкой длины, диапазонов и типа. Паники не должны завершать службу,
  ошибочный пакет только отбрасывается.
- `\\.\pipe\rcs-agent` использует DACL и `FILE_FLAG_FIRST_PIPE_INSTANCE`.
- `SoftwareSASGeneration` меняется только с подтверждения пользователя в фазе 6.

## Журнал

`%ProgramData%\RCS\logs\audit.log`: успешные и неудачные входы, блокировки, запуск и завершение сессий,
операции с файлами. Журнал ограничен ротацией и не содержит секретов.

## Логи и пакеты для проверки

- `collect-logs.ps1` не включает каталог `secrets`.
- В журналах заменяются внешние IP, имена компьютера и пользователя, значения cookie и токенов.
- `system.json` содержит публичные DNS-записи домена, включая A-запись с внешним IP сервера.
- Перед передачей пользователь может открыть архив: он содержит только текстовые файлы и отчёты JSON.
- `server-logs/` и `dist/` не попадают в git.
- У пакета есть SHA-256, который выводит `package.ps1` и проверяет `install` на сервере.
- Удалённый отладочный доступ к серверу не добавляется.
- После фазы 3 ни один пакет не содержит режима работы без авторизации.

## Чек-лист перед открытием 8443/UDP

- [ ] Без cookie все `/api/*`, кроме входа, возвращают `401`.
- [ ] WebSocket отклоняется без сессии и с чужим `Origin`.
- [ ] Предварительная сессия не даёт доступа к сигналингу и файлам.
- [ ] Ограничение попыток проверено тестом.
- [ ] TOTP нельзя использовать повторно.
- [ ] HTTP переадресует на HTTPS, сертификат действителен.
- [ ] `rcs-web` слушает только `127.0.0.1`.
- [ ] Секреты не найдены в репозитории и журналах.
- [ ] `cargo audit` и `npm audit` без критических находок.

## Поддержание

- Перед каждой фазой с новой сетевой поверхностью: обзор безопасности изменений.
- Перед закрытием фаз 3, 6, 7 и 8: `cargo audit`, `npm audit`, ревью этого документа.
- Обновления Windows, драйверов и зависимостей не отключаются навсегда: перезагрузка планируется.
